# Резюме `/resume` — A4-документ

Самостоятельный документ: `src/components/ResumePage.astro` рендерит собственный `<html>`,
не использует layout, не подключает Tailwind. Внешних зависимостей для PDF нет — кнопка
«Скачать» вызывает `window.print()`.

## Структура файла

| Часть                     | Что содержит                                                     |
| ------------------------- | ---------------------------------------------------------------- |
| frontmatter               | Импорт шрифтов, сервисы, per-locale UI-строки, локальные фильтры  |
| `<head>`                  | `noindex, nofollow`, favicon, pre-paint скрипт темы хрома         |
| `.toolbar.no-print`       | Назад на сайт, чип «A4 · N страниц», кнопка печати `#download-btn` |
| `#stage > #paper > #flow` | Плоский список блоков до пагинации                                |
| `<script is:inline>`      | Пагинация и масштабирование                                       |
| `<style is:inline>`       | Вся типографика листа, `@page`, правила печати                    |

## Данные

Контент приходит через те же сервисы, что и сайт. Специфика резюме — локальная:

- `HIDDEN_SKILLS` — список заголовков категорий, которые не идут в CV (сейчас
  «Forms & Validation» во всех трех локалях); фильтруется `tech.categories`.
- `splitHighlight(h)` — `"Проект — описание"` превращается в жирный зачин плюс текст,
  чтобы буллеты читались за шесть секунд.
- `fileName` — `Имя-Фамилия-CV-XX`; ставится в `document.title`, потому что имя файла в
  диалоге печати берется из заголовка документа.

Контакты выводятся как `mailto:`, `tel:` и https-ссылки — это часть ATS-контракта.

## Пагинация

Шаблон выдает **плоский** список атомарных элементов `.block` внутри `#flow`. Скрипт
раскладывает их по настоящим A4-боксам:

1. `#flow` удаляется, `#paper` очищается, создается первая `.page` с `.page-body`
   фиксированной высоты (тип-область листа).
2. Блоки добавляются по одному; как только `scrollHeight` превышает `clientHeight`,
   создается новая страница и блок переносится туда.
3. Заголовки секций (`.sec`) и шапки записей (`.entry-head`), оставшиеся последними на
   странице, перетаскиваются вперед — сирот в подвале листа не остается.
4. Каждой странице дописывается футер `Имя — N / M`, счетчик в тулбаре обновляется.

Пагинация запускается после `document.fonts.ready`: метрики до загрузки шрифтов дают другую
разбивку.

**Следствие для разметки:** новый элемент должен быть прямым потомком `#flow` с классом
`block`, иначе он не попадет в раскладку. Вложенные блоки не режутся между страницами —
атомарность держим на уровне абзаца/строки.

**Следствие для стилей:** страницы создаются в рантайме, поэтому scoped-стили Astro на них
не навешиваются — отсюда `is:inline` у `<style>`. Не переводить в scoped.

## Печать и экран

`@page { size: A4; margin: 0 }` плюс `break-after: page` на боксах: браузер печатает те же
самые страницы, которые показаны на экране. **Превью — это и есть PDF, страница в страницу.**

`fit()` масштабирует всю стопку трансформом на узких экранах (A4 = 794 CSS-px), вместо
переверстки: пропорции листа сохраняются. Пересчитывается на `resize`.

## Тема

Второй инлайн-скрипт в `<head>` читает `v2-theme` из `localStorage` до первой отрисовки: хром
(тулбар и подложка) следует за темой, закрепленной на сайте. Токены продублированы локально
как `--c-*` и применяются **только** к хрому — **лист всегда белый**. Палитра бумаги и правила
оформления листа описаны в разделе «Дизайн».

## ATS-контракт

Одна колонка, стандартные названия секций («Professional Summary», «Work Experience»,
«Technical Skills», «Education», «Languages»), настоящий выделяемый текст. Ни иконок, ни
изображений, ни таблиц, несущих данные, — парсеры ATS и ИИ-скринеры читают документ линейно.

Нарушение любого из этих пунктов ради красоты — регресс, а не улучшение.

## Индексация

Страница `noindex, nofollow` и исключена из sitemap фильтром в `astro.config.mjs`: один и тот
же контент не должен конкурировать сам с собой в выдаче.
